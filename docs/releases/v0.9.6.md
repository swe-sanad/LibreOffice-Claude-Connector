# v0.9.6

The last release you saw was v0.9.5. That one made Claude a safer collaborator. This
one turns the server into something that can carry a document from a blank page to a
finished file — and reaches deeper into LibreOffice for things a document actually
needs before it's ready to send: real metadata, print setup, accessible PDFs, and a
much bigger Form menu.

## What's new

**A guided session, without hiding any tool.** Claude Desktop can now surface three
prompts for you to pick from — `start_document`, `review_document`,
`finish_document` — and Claude has a new `document_lifecycle` tool that reports where
a document actually stands: SETUP (title, language, house style), AUTHORING (content,
headings, broken formulas), or CLOSING (metadata, alt text, saved state, export) —
with what's done, what's left, and the exact tool for the next step. This is derived by inspecting
the document itself, not stored anywhere, so it survives a restart and every tool
still works in every phase — asking for the PDF on message one just works.

**Find & replace keeps your formatting properly now.** A replacement that spanned part
bold/part plain text used to come back chopped along the old boundaries. Each match is
now replaced as a whole and takes the formatting of its first character
(`preserve_formatting=false` for the old raw behavior). Both Writer and Calc find &
replace, plus Writer's search, now also support **regular expressions** with
`$1..$n` backreferences — and Writer search can target a paragraph style directly
(e.g. "find every Heading 1").

**Number formats that respect your locale.** `calc_format_range` now takes a
`number_preset` (currency/percent/date/time/datetime/number/text) plus a `locale`,
resolved the way LibreOffice itself resolves it — so an Arabic-Libya currency format
comes out right without anyone hand-writing a format code.

**Notice when something changes underneath you.** `document_watch` tells you if a
document changed since you last checked, and separates your own edits from the
user's — useful before a long multi-step operation.

**Documents are more complete when Claude hands them back:**
- Full **Dublin Core metadata** (File ▸ Properties ▸ Description) — coverage,
  identifier, rights, source, type, contributor, publisher, relation, and the
  document language a screen reader announces.
- **Print settings** — printer, paper, orientation, and the Writer/Calc-specific
  print switches (right down to right-to-left booklet printing).
- **`set_alt_text`** — alt text and the "decorative" flag on images and shapes. Without
  it an exported PDF has all the right structure while every picture stays silent to a
  screen reader.
- **Content controls** — the modern Form ▸ Content Controls family (rich text, plain
  text, checkbox, dropdown, combobox, date, picture) that survive a `.docx` round trip.
- **Form controls: 5 kinds → 19** — the rest of the Form menu that doesn't need a
  database: radio buttons, comboboxes, group boxes, formatted/numeric/currency/date/
  time fields, file pickers, image buttons, scrollbars, spin buttons, and more.
- **Accessible and fillable PDF export** — tagged PDF, PDF/UA-1, bookmarks, real
  fillable AcroForm fields from your form controls, watermarks, and an owner
  password with separate print/modify/copy/annotate permissions.

## How to use it

Just open LibreOffice and start talking to Claude — the three phases below are a
mental model, not a mode you switch into. In Claude Desktop you'll also see the
`start_document`, `review_document`, and `finish_document` prompts you can pick
directly instead of typing.

1. **Setup** — "Start a new report" or "open last week's budget sheet." Claude checks
   `document_lifecycle` and, if there's no title or language set yet, asks you before
   it fills those in for you.
2. **Authoring** — "Add a heading, then a summary paragraph, then a table of the Q3
   numbers." Claude writes the content, and if you ask it to "make the headings
   consistent," it can now do that with a regex-powered find & replace across the
   whole document, formatting intact.
3. **Closing** — "Get this ready to send." Claude checks the document's metadata,
   language, and alt text, tells you what's still missing (and asks before filling in
   anything opinionated), then exports a tagged, accessible PDF — or a fillable one,
   if you built a form.

At any point you can skip ahead — "just export the PDF" on the very first message
works, because no tool is ever hidden behind a phase.

## What makes this server unique

- **Zero third-party dependencies.** The whole server runs on LibreOffice's own
  bundled Python — no `pip install`, no vendored packages, no compiled wheels. The two
  comparable open-source projects we studied both vendor packages into the extension
  itself, and one runs its data-science layer as a separate Docker sidecar service.
  This project stays a single, self-contained install.
- **Works with any stdio MCP client.** Claude Desktop, Claude Code, Cowork — anything
  that speaks MCP over stdio. The rivals are HTTP-in-extension first.
- **An everyday tier, not a flat 100+ tool list.** 51 tools by default instead of all
  188 competing for attention on every message, with the rest one `dispatch` call
  away — not a hard wall.
- **Per-call undo grouping** so a multi-step edit reverts in one Ctrl+Z, wherever
  LibreOffice's own undo model allows it (see the one exception below).
- **Crash and hang recovery**: `lo_health` checks before doing anything risky,
  `lo_recover` drives LibreOffice's own crash recovery without you clicking through a
  dialog, and `checkpoint_document` snapshots a document you can roll back to.
- **A per-call timeout** (120s by default) so a stuck LibreOffice dialog can no longer
  wedge the whole session silently.
- **Structured errors with hints** — `{code, retryable, message, hint}` — so Claude
  can tell "retry this" from "ask the user" from "wrong tool for this document type."
- **Claude-native end to end.** The `.oxt` extension (Claude inside LibreOffice) and
  this MCP server (LibreOffice as a tool for Claude) are one product built for one
  model family, not a generic multi-provider layer.

To be fair about where the rivals are ahead: both are an order of magnitude larger,
actively developed, and cover Impress, Draw, and Base — we only cover Calc and Writer.
Closing that gap is tracked in `docs/PLAN-IMPRESS-BASE-DRAW.md`, not attempted here.

## Known limitation — please read

LibreOffice does not record a bulk cell-range write (`calc_write_range`, and the
number-cleanup part of `calc_clean_data`) for undo — the Edit menu shows an undo entry,
but pressing Ctrl+Z will **not** restore the old values. This is a real limitation in
LibreOffice itself. The protection is `checkpoint_document`: ask Claude to take a
checkpoint before a big bulk edit, and you can roll all the way back to it.

## Upgrading

Install this `.mcpb` the normal way through Claude Desktop's extension manager. If it
was previously refused as a downgrade because of a stray higher build number, remove
the existing LibreOffice Connector extension first, then install fresh.
