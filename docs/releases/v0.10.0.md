# v0.10.0 — the everyday-user surface

Every release up to now grew the tool count: 7 → 50 → 61 → 137 → 170. That was the
right pressure for an expert operator driving a complex document, and it is why this
server can do things its siblings cannot. It is the wrong pressure for the person this
release is about — a student formatting a gradebook, or anyone who just wants a table
to stop looking like a CSV dump.

**Nothing is removed.** All 174 tools are still there and still reachable. What changes
is how many of them Claude has to look at.

## The surface, tiered

`tools/list` now advertises a focused **32-tool everyday set** by default. The other 142
stay reachable by name through the `dispatch` tool, whose catalog is the authoritative
list of what is possible.

|  | schema sent | tools to choose between |
|---|---|---|
| before | 84 KB (~23k tokens, every conversation) | 170 |
| after | 15 KB (~4k tokens) | 32 |

That is an **82 % cut** in fixed context cost, and — more importantly — 68 `calc_*`
lookalikes no longer compete for the answer to "make this table look nice".

Tick **"Advertise all 174 tools"** in the extension settings (or set `LO_TOOLS=full`)
to get the flat surface back. Power users lose nothing.

## One Ctrl+Z per action

Every mutating tool now runs inside a single undo context, so one Ctrl+Z in LibreOffice
reverts a whole tool call instead of one cell of a 500-cell write. Tools reached through
`dispatch` and `batch` inherit it.

Measured: `calc_format_table` performs seven UNO property writes (borders, header
weight, background, font colour, number format, autofit, freeze) and produces exactly
**one** undo entry, which a single undo fully reverts.

## Four tools that match how people actually ask

- **`calc_format_table`** — header emphasis + border grid + auto-fitted columns +
  frozen header row in ONE call. Presets `clean` / `report` / `financial`. Replaces a
  five-call `format_range` → `set_borders` → `set_dimensions` → `sheet_properties` chain.
- **`calc_clean_data`** — trim whitespace, turn numeric-looking text into real numbers,
  drop fully empty rows. Formula cells are never rewritten.
- **`writer_format_document`** — base typography (applied to Western, Complex and Asian
  scripts, so an Arabic base font actually takes effect), line spacing and page margins.
  Presets `report` / `essay` / `letter`.
- **`calc_overview`** — a cheap structural map of a workbook: per sheet the used range,
  its size, a few sample rows, and whether row 1 looks like headers. Bounded output
  whatever the file size, unlike `read_spreadsheet` which dumps every cell of every sheet.

## One less install step

The agent-acceptor `.oxt` now ships **inside** the `.mcpb`. When the server is connected
over a socket rather than the acceptor pipe, `lo_status` hands back the exact
`unopkg add` command for the bundled copy — so a user who already had LibreOffice open
gets a one-line fix instead of a download link.

## Fixed

- **`getFormulaArray()` marks numeric-looking TEXT with an apostrophe.** Calc's
  force-text marker means `" 3 "` reads back as `"' 3 "`, so a plain `.strip()` leaves
  `"' 3"` and the cell stays text. Caught by live verification: `calc_clean_data`
  reported six cells trimmed and looked correct while leaving every number as text — the
  `=SUM()` below them evaluated to **0.0**. The marker is now dropped only when the
  remainder really parses as a number, so genuinely textual cells keep it.
- **`.vscode/mcp.json`** had a trailing comma, making it invalid strict JSON.

## Known issue — bulk range writes are not undoable

LibreOffice does not record `setDataArray` / `setFormulaArray` for undo. Both register
an entry that appears in Edit ▸ Undo and is consumed by `undo()`, but the cells keep
their new values (verified against 25.2.3.2):

| write path | undo entry | contents revert |
|---|---|---|
| `setString`, property sets, grouped contexts | yes | **yes** |
| `setDataArray` / `setFormulaArray` | yes | **no** |

So `calc_write_range` and the trimming half of `calc_clean_data` are outside the undo
grouping above. This is **not worked around**: per-cell `setString` is O(n) UNO
round-trips (unusable on a 10k-cell write), and a Python `XUndoAction` would leave a
dead proxy in the document's undo stack whenever the server restarts. `calc_clean_data`
states the caveat in its own description. Full detail in
[`docs/KNOWN-GAPS.md`](../KNOWN-GAPS.md).
