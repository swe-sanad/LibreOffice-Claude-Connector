# v0.9.8

A patch release for one specific bug: **the `.mcpb` launcher could crash and disconnect
Claude Desktop from a perfectly healthy server.**

## Fixed

**The launcher silently died on a broken stdio pipe.** `mcpb/index.js` wired `process.stdin`,
`child.stdout` and `child.stderr` together with plain `.pipe()` calls, which forward data but
not errors. The instant either end of a piped stream errored — most likely Claude Desktop
closing its side while reclaiming an idle Electron `UtilityProcess` — Node's default action for
an unhandled `'error'` event is to throw, killing the whole launcher before it ever reached our
own exit-code logging. That's why Claude Desktop's MCP log showed a generic "Server transport
closed unexpectedly" / "Server disconnected" with no diagnostic from us, after idle gaps ranging
from a few minutes to over an hour.

Reproduced end-to-end against the real launcher and a real LibreOffice Python: destroying the
wrapper's stdout mid-flight and forcing a write into it crashed the old code with the exact
`EPIPE: broken pipe, write` stack trace and exit code 1. The new `safePipe()` wrapper attaches
`'error'` listeners to both ends of each pipe and swallows EPIPE/ECONNRESET instead of crashing,
so a transient broken pipe no longer takes down a healthy Python server underneath it.

If you were seeing the LibreOffice Connector extension flip to "failed" in Claude Desktop after
sitting idle, this is that bug.

## Also in this release (already on `master`, now formally tagged)

- **The server is a package, not one 9,000-line file.** `mcp/libreoffice_mcp.py` is now ~240
  lines holding only the protocol; the 218 tools live in `mcp/loconn/`, one module per
  application per concern, self-registering through a validating `registry.py`.
- **Calc counterparts of the Writer supporting tools** (215 → 218): `calc_find`,
  `calc_set_document_defaults`, `calc_set_header_footer`.
- `print_settings` fixed for Calc (was raising `UnknownPropertyException` for every option).
